## Wazuh deployment

The official Wazuh 4.14 installation assistant was downloaded from `packages.wazuh.com` and run in all-in-one mode. The deployment installed:

- Wazuh indexer
- Wazuh manager
- Filebeat
- Wazuh dashboard

The generated dashboard administrator credential was handled privately and replaced with a user-selected policy-compliant password using the official Wazuh password-management tool. No password or credential is stored in this repository.

The Wazuh APT repository was disabled after installation, as recommended by Wazuh, to prevent accidental component upgrades. Normal Ubuntu repositories remain enabled.

## Host firewall policy

## Acceptance results

- `wazuh-indexer`, `wazuh-manager`, `filebeat`, and `wazuh-dashboard` all reported `active`.
- The dashboard listened on TCP 443.
- The Wazuh API listened on TCP 55000 for local component communication.
- Local HTTPS returned `HTTP/1.1 302 Found` with a redirect to `/app/login`.
- Remote HTTPS from `admin01` returned the same `HTTP/1.1 302 Found`.
- A new SSH connection from `admin01` succeeded after UFW was enabled.
- The dashboard loaded from `admin01` and accepted the privately changed `admin` credential.
- On 2026-07-31, the dashboard reported two active agents and zero disconnected agents after enrolling `admin01` and `ubuntu-01`.

Firefox briefly retained a stale dashboard session and displayed a blank-screen route and TLS connection errors after the password and service changes. Service, listener, firewall, local HTTPS, and remote HTTPS checks all passed; closing/retrying the browser session restored the dashboard without weakening the firewall.
